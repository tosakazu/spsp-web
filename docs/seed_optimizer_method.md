# シード被り回避最適化 — 方式詳細ドキュメント

対象: `site/seeding/seed_optimizer.js`(探索・スコア) / `site/seeding/seed_data.js`(データ構築) /
`site/seeding/seed_worker.js`(実行基盤)。設計経緯・API 契約は
[seed_collision_avoidance.md](seed_collision_avoidance.md) を参照。本書は**アルゴリズムそのもの**を
数式レベルで説明する。

---

## 1. 問題設定

**入力**
- `ranking`: SPSP 総合評価順の参加者 uid 列(長さ N)。これが「元順位」= 基準シード順。
- `poolCount` P と大会形式(`DOUBLE_ELIMINATION` 等)。
- 都道府県マップ `prefByUid`(SPSP の居住地データ。南関東 = 埼玉/千葉/神奈川/東京 などの
  地域グルーピングを適用後)。
- 直近対戦ペア罰則 `recentPair`(§3.2 の式で全対戦履歴から事前計算)。

**出力**
- シード順 permutation `seedOrder`(と、そこから snake で一意に決まるプール割当・
  DE 時はプール内ブラケット順)。

**目的**: 元順位をできるだけ保ったまま、(a) 同一地域の同プール被り、(b) 直近対戦ペアの
早期再戦、を最小化する **制約付き組合せ最適化(置換空間上の探索)**。

## 2. シード → プールの構造(snake / 蛇行割当)

シード番号 s(0始まり)のプールと行(row = プール内順位)は決定的:

```
row(s) = floor(s / P)
col(s) = s mod P
pool(s) = col(s)            (row が偶数)
        = P - 1 - col(s)    (row が奇数)   ← 蛇行で折り返す
```

つまり seed1..P が各プールの1位、seed P+1..2P が2位(逆順)、…。
**シード順を決めればプール構成もプール内順位も一意に決まる**ので、探索の状態は
seedOrder(uid の並び)ただ1つで表現できる。

プール内のブラケット配置は標準シードスロット順(`seedSlotOrder`: 1,8,4,5,2,7,3,6 …)で
固定し、プール内順位 i, j のペアが**最初に当たり得る回戦** `earliestMeetRound(slot_i, slot_j)`
を bit 演算(共通祖先の高さ)で O(1) 算出する。

## 3. 目的関数(最小化)

### 3.1 ペア罰則

すべてのペア (a,b) に対して:

```
pp(a,b) = W_region · region(a,b) + W_recent · recent(a,b)
          (既定 W_region = 1.0, W_recent = 0.3。大小は自由 = どちらを優先するかは運用判断)
```

**地域成分**: 同一地域(グルーピング後)なら県別出場人数 c に応じた連続重み、違えば 0:

```
region(a,b) = 1/√c   (pref(a) == pref(b) == 当該地域, c = その地域の出場人数)
```

少数県ほど重い=「その県で1つしかない被り」を優先的に解消する。ハード制約ではなく
連続重みなので、多数派県も鳩の巣を超えない範囲でいい感じに分散する。

**直近対戦成分**(`seed_data.js` で事前計算):

```
1試合の罰則  v = log2(max(nent, 2)) · decay(経過日数)
decay: 制御点 [(0,1), (30,1), (91,0.5), (182.5,0.25), (365,0)] の線形補間(1年で0)
ペア集計    recent(a,b) = max(全対戦の v)   (既定 'max'。'sum' で合算に変更可)
```

大規模大会での最近の対戦ほど重い。1ヶ月以内はフル、以後線形に減衰して1年で忘れる。

### 3.2 全体スコア

```
S(order) =   Σ_{同プールの全ペア} pp(a,b)                       … inter 成分(プール所属のみに依存)
           + Σ_{同プールの全ペア} rw(earliestMeetRound(a,b)) · pp(a,b)   … intra 成分(DE のみ)
           + W_order · Σ_i |seed_i − origRank_i|^orderPow        … 元順位ズレ罰則
```

- 回戦重み `rw` 既定 `[1.0, 0.6, 0.4, 0.06, 0.02]`(R1..R5+、超過は末尾)。R1-R3 の
  早期被りを強く罰し、勝ち上がった末の再戦(R4+)はほぼ許容する。
- 元順位ズレ罰則は既定 `W_order = 0.001, orderPow = 2`。タイブレーカー級の重みだが
  2乗なので大移動(±20〜30)には効き、微調整(±1〜2)にはほぼ効かない。

## 4. 硬い制約(可動窓。すべて**初期位置基準**)

swap 候補は以下を**両者とも**満たすときのみ有効:

| 制約 | 内容 | 既定 |
|---|---|---|
| `k_inter(row)` | row(プール内順位)の選手が初期プールから動けるプール数 | 1・2位=0(固定) / 3位=±1 / 4位=±2 / 5位=±4 / …倍々 |
| `k_intra(rank,M)` | プール内で初期順位から動ける順位数(M=プールサイズ) | 上位 1/4 = 0(固定) / 残り ±1 |
| `maxSeedShift` | 最終シード**番号**の元順位からの最大変位(inter+intra 合成後) | null(無制限) |

- 合成変位の上界: inter は同一 row 内(≤ P−1 シード) + intra ±1 行(≈ P シード) = **最大 2P−1**。
  snake 番号の折返しがあるため「プール内順位を1つ下げるだけ」が端のプールでは
  シード番号 +31(P=16) に見える。これを番号ベースで直接抑えたいとき `maxSeedShift` を使う。
- 制約は「前ステップからの相対」ではなく**常に初期順位基準**なので、swap を何回
  繰り返しても窓の外へは出られない(ドリフトしない)。

## 5. 2フェーズ分解

全置換空間(N!)は探索できないので、構造を使って2段に分ける:

1. **inter フェーズ**: 同一 row の2シードの交換のみ(=プール所属だけが変わる。
   プール内順位は不変)。スコアは inter 成分 + order 罰則で評価。
2. **intra フェーズ**: プールごとに独立へ分解し、プール内の2順位の交換のみ
   (=当たり回戦だけが変わる)。プール p のスコアは
   `Σ rw(meet(i,j))·pp + order 罰則(グローバルシード位置換算)` で評価。

分解が正当な理由: inter 成分はプール所属のみに依存し(回戦非依存)、intra 成分は
プール内配置のみに依存するため、フェーズ間の干渉は order 罰則経由の弱いものだけ。
intra はプール間で完全に独立なので逐次処理でも状態が干渉しない。

**Δ の増分評価**: 1 swap のスコア変化は影響ペアだけ再計算する
(inter: 2プールの内部ペア和、intra: 同プール内の相手全員 = O(M))。
テストで「Δ 累積 = 全再計算」の一致を常時検証(`_verifyDelta`)。

## 6. 探索アルゴリズム

共通の近傍: 制約(§4)を満たすランダムな 2 要素 swap(最大40回リトライで提案)。

| モード | 内容 |
|---|---|
| `hillclimb` | Δ ≤ 0 のみ採用。一定回数改善なしで打切り |
| `sa` | Δ > 0 も確率 `exp(−Δ/T)` で採用。幾何冷却 `T ← 0.999·T`(`saMinT=1e-4` で下限) |
| `multistart-*` | 上記を独立に複数回実行しベストを採用 |
| `multistart-sa` | **既定**。restarts=15 |

- **初期温度 T0 の自動推定**: 近傍 30 サンプルの平均 |Δ| × 1.5(下限 1e-3)。
  「平均的な swap が最初は5割前後の確率で通る」スケールに合わせる。
- 反復数: `maxIters = max(500, 状態サイズ × 1000)`(既定)。
- **multistart の実装は worker 側**(`seed_worker.js`): 各リスタートは
  「同じ初期解(元順位 snake)+ 乱数シード違い(`rngSeed + 97k`)の SA」。
  初期解のランダム攪乱はベンチで悪化したため使わない(良い出発点の維持が強い)。
  ベスト選択は `after.total` 最小、同点なら order 罰則が小さい方
  (被り全解消解が複数出たとき「無駄にシャッフルされた解」を返さないため)。
- Web Worker 上で非同期実行。進捗コールバック・途中停止(その時点のベストを返す)対応。

## 7. 決定性・fail-loud

- 乱数は xorshift 系の自前 PRNG(`rngSeed` 既定 12345)。**同じ入力+シードなら同じ出力**。
- パラメータの退行系(空 roundWeights、負の k 配列、負/非数の maxSeedShift、未知 mode)は
  **黙って降格せず throw**。「エラーなしで恒等解が返って
  最適化したつもりになる」事故を過去に踏んだため。

## 8. 形式ゲーティング

| プール数 × 形式 | inter | intra |
|---|---|---|
| P≥2 × DE | ○ | ○(`enableIntra=false` で off 可) |
| P≥2 × 非DE(RR等) | ○ | ×(プール内の当たり順が確定しないため) |
| P=1 × DE | ×(プール1つ) | ○(常時。唯一の回避手段なのでトグル対象外) |
| P=1 × 非DE | 非対応(throw ではなく unsupported を返す) |

※ intra 最適化を off にしても、DE なら既定ブラケット順の当たりは確定しているので
**プール内レポート(§9)は常に出す**(2026-07 修正)。

## 9. レポート

`fullReport` が before(元順位 snake)/after のスコア内訳と改善率、および残存懸念を
4セル {プール間, プール内} × {同一地域, 直近対戦} で返す。直近対戦の**表示**は最終対戦が
半年(`reportRecentMaxDays=182.5`)以内のものだけ(スコア計算は全期間)。地域は
「分離可能(出場 ≤ P)」と「多数派(> P、鳩の巣で不可避)」を区別して報告する。

## 10. 計算量・実測

- スコア構築: recentPair は疎(実対戦ペアのみ)。ペア罰則参照は O(1)。
- 1 iter = 近傍提案 + Δ 増分評価(inter: O(プールサイズ²) 相当の部分和差分、intra: O(M))。
- 既定(multistart-sa, restarts 15, N≈128)で **~10-20 秒**(worker 上、UI 非ブロック)。
- 実大会ベンチ(スマバト#67 ほか5大会)で R1-R2 の直近再戦を概ね 1/2〜1/3 に削減。
  restarts は ~6 で頭打ち傾向。
