## 概要

まだ開始時刻を迎えていない大会について結果を予想するエンタメ機能。
ビルド時に予想を採点し、正答率やポイントを競い合えるようにする。

## 予想パターン (どれか一部だけの予想が基本線)

全部予想は大変なので、**一部だけの予想が主に使われる想定**。

| パターン | 内容 |
|---|---|
| 全試合 (セット数込み) | 全トーナメントの勝敗をセット数込みで予想 |
| 全試合 (勝敗のみ) | 同上、セット数は考えない |
| 全体順位のみ | トーナメント全体の最終順位だけ予想 |
| トップ N | 上位 N 人だけ予想 |
| 特定プール | 指定プールの中だけ予想 |
| 特定プレイヤー | 1 選手の成績 (順位等) だけ予想 |
| 特定マッチアップ | 1 試合の勝敗 (セット数込み?) だけ予想 |
| アップセット予想 | 発生する番狂わせを予想 |

## 認証 — 2 系統

| | 選手認証 | 一般認証 |
|---|---|---|
| 方式 | start.gg OAuth (**実装済み**: `action:login`) | Google 認証 |
| 対象 | SPSP にデータがある選手 | 誰でも |
| ユーザー名 | start.gg 由来 | **登録が必要** (GAS 経由で管理) |

- どちらでも予想を送れるようにする。
- **Google のユーザー管理は GAS 側で完結**させ、ビルドサーバーと独立させる。
  ビルドを待たずに登録・利用できるのが理想 (キャラ投票のように「反映は次回ビルド」
  ではなく、登録した瞬間から予想を送れる)。
- Google 認証の実装候補: GAS Web アプリ自体を `ANYONE` (Google ログイン必須) にする
  別デプロイを立てる / Google Identity Services (GIS) の ID トークンを GAS で検証する。
  現行の `ANYONE_ANONYMOUS` エンドポイントとの共存方法は要検討。

## 採点・ランキング (集計はビルド時)

- 予想の正答率などを競い、ポイントを競って表彰などができるといい。
- 予想者用のプレイヤーページもあってよい。
- 予想力ランキングの集計方針 (要検討):
  - 難しい予想ほど高ポイント
  - 大規模な大会ほど高倍率
  - 集計対象の大会 (LV が付くような大会?) の方が高倍率
- **競馬を参考にする**。ただし:
  - 参加者数が少ない + 予想が多岐に渡るので、パリミュチュエル方式は成立しにくく、
    **公式でオッズを出してあげる必要がある**のが難しい (モデル由来の勝率
    → オッズ換算が候補。スコアシミュレーション (site/sim/) の calc.js が流用できそう)
  - **2 部門制**が良さそう:
    1. ギャンブルとしての最適行動を競う部門 (オッズ × 的中で持ち点を増やす)
    2. 純粋な予想精度を追い求める部門 (オッズに依らない的中率・スキルスコア)

## 実装の足がかり (現状資産)

- 開始前大会の参加者データ: `site/data/upcoming_entrants.json`
  (nightly が `[2.6/5]` で取得。スコアシミュレーションが使用中)
- 勝率モデル: `site/sim/` の calc.js (v3 移植・glicko2)。オッズの元にできる
- ブラケット構造・進出予測: `site/seeding/seed_share.js` + `site/bracket/`
  (シード通り前提の勝ち上がり、実プール 197 件で検証済み)
- 予想の受け口: GAS `doPost` に `action: "predict"` 等を足す形
  (token 検証・シート append・rate limit は実装済みの仕組みをそのまま使える)
- シートは用途ごとに分ける (`getDataSheet_(name, header)` で追加は 1 行)
