# プレイヤーカードの二つ名 — 設計

2026-10-01。Figma「submit」ver.1.5 の二つ名 (カード左上の「// 前半 後半」) を、編集ページで選べるようにする。
2026-10-14 に「過去に引いたものが変わらない」形 (記録に足していくだけの抽選) に作り直した。

## 二つ名の一覧 (ID 管理)

- 一覧 = `site/js/titles_ja.js` の行 (`[番号, 位置, 種類, 文字, { chars, pref, added, retired }?]`)。編集ページの採用一覧から書き出す (手で直さない)。
  `site/js/titles.js` が `TITLES[lang]` の形 (`{ id, part: 'pre' | 'post' | 'both', text, unlock: 'initial' | 'random' | 'char' | 'pref', added, retired?, genre?, kind?: 'move', chars?, pref? }`) に直す。
  北米 (`en`) は空 (英語の一覧ができるまで北米では二つ名を出さない: `region/config.js` の `features.titles: false` で編集ページの欄とヘッダーのお知らせを出さない。
  ビルドは日本以外の地域で `titles_ja.js` を空の一覧に差し替える = 北米のページに日本語の一覧を入れない)。
- **使える位置 (part)**: 前半だけ / 後半だけ / どちらでも (`usableIn(t, slot)`)。「どちらでも」は前半・後半の両方のリールに出る。
- **id**: `<言語>-<4 桁>` (`ja-0001`)。番号は 9999 まで。カードの設定にも記録にも id (番号) だけを持つ。一度使った番号は別の文言に使い回さない。
- **言語ごとに別の一覧**: 日本の地域は `ja`、北米は `en` (`region/config.js` の `titleLang`)。英語は日本語の訳ではなく別に作る。
  表示の言語 (UI) を切り替えても二つ名の表記は変えない。
- **公開したら消さない・位置を変えない**: 持っている人のカードから消えるため。やめるときは `retired` (廃止日)。持っている人は持ったまま、廃止日からは引かない。
  `tests/frontend/titles_frozen.json` に公開済みの番号と位置を持ち、テストが消えていないこと・位置が変わっていないことを確かめる
  (一覧を書き出したら `node tools/titles/freeze_titles.mjs`)。文字の直し (誤字など) とジャンルの変更はしてよい (これから引く分にだけ効く)。
- **足すとき**: `added` = 配り始める日。書き出しの道具が新しい行に明日 (JST) を入れる。その日から引ける。

## 持っている二つ名 = 記録 (D1)

- D1 `title_owned (uid, lang, bits, updated, n_pre, n_post, PRIMARY KEY (uid, lang))` WITHOUT ROWID (0005・0007・0008)。
  - `bits` = 持っている二つ名の番号を位置にしたビット列 (base64url、詰め物なし、末尾の 0 は落とす。`site/js/title_bits.js`)。
    1 人約 1.2 KB (一覧の最後の番号まで全部持っても同じ)。Worker は 4 KB (番号 32767) まで受ける。
  - `n_pre` / `n_post` = 大会で引いた回数 (最初の配布は数えない)。
  - `updated` = 最後にビットが増えた日 (YYYY-MM-DD)。
  - WITHOUT ROWID: ふつうの表だと 1 行書くたびに主キーの索引にも書き、D1 の書き込み行数が倍になるため。
- **記録に足していくだけ**: 抽選の結果は記録に残り、あとで計算し直さない。なので、一覧の追加・廃止・ジャンルの変更、遅れて取れた大会、
  大会の取り消し・日付の直しがあっても、過去に引いたものは変わらない (2026-10-14 ユーザーの要望)。
  - 毎回の同期で「出た大会から決まる回数」(`drawTargets`) と記録の回数の差だけ、その時点の一覧から新しく引く (`advanceTitles`)。
  - 大会の取り消しで回数が減ったときは何も引かず、記録の回数のまま (引いたものは消さない)。回数が記録を超えたら、超えた分だけ引く。
  - 遅れて取れた大会は、増えた回数の分だけ (次の同期で) 引く。
  - 配る数を変えるときは `DRAW_RULES` に「この日以降の大会」の行を足す (書き換えると過去の大会の回数が変わり、その分をまとめて引くことになる)。
- **最初の配布**: 記録を初めて作るときに、ジャンルごとに `INITIAL_COUNTS` の数ちょうど
  (前半 50 = 汎用 25・スマブラ 15・元ネタ 10、後半 100 = 汎用 40・スマブラ 20・技名 25・元ネタ 15。2026-10-14 ユーザー決定で 60/140 → 50/100)。
- **大会**: 公開日 (`TITLE_LAUNCH` 2026-10-15) 以降の大会だけ (公開前の大会はさかのぼらない。2026-10-14 ユーザー決定)。
  本戦で 1 試合以上した大会 1 つにつき前半 4、試合 2 つごとに後半 4 (端数は次の大会に持ち越す。試合 0 の大会・DQ の試合は数えない。2026-10-14 ユーザー決定で 3 → 4)。
  試合数は本戦と下位クラス (B〜E クラスの仮想大会の行、`parent_event_id` あり) の合計。下位クラスの行は前半には数えない (本戦と同じ大会なので)。
- **引き方**: 大会での k 回目は、ジャンルを `DRAW_WEIGHTS` の比 (前半 汎用 3 : スマブラ 2 : 元ネタ 1、後半 汎用 6 : スマブラ 3 : 技名 3 : 元ネタ 2) で決め
  (`hash32("<uid>|<pre|post>|<k>|genre")` の上の位)、その中で選手ごとの引く順番 (`hash32("<uid>|<id>")` の小さい順) のいちばん前の、まだ持っていないもの。
  そのジャンルを引き切ったら同じ位置のほかのジャンルから。前半・後半をまたいでは引かない。候補は `added` ≦ その日 < `retired` のもの。
  引く順番は二つ名ごとのハッシュなので、一覧に足しても消しても、ほかの二つ名どうしの順番は変わらない。
- **キャラ・都道府県**: `char` = メインキャラ (`players/<uid>.json` の `characters[0]`。キャラ投票はビルドが並びに反映済み) が `chars` のどれかなら持つ
  (「◯◯使い」= 後半、「◯◯使いの」= 前半。「ピーチ / デイジー」のような 1 つの ID は両方)。`pref` = 都道府県 (`data/player_prefectures.json`) が `pref` なら持つ
  (「神奈川の」= 前半)。同期のたびに記録に足す (キャラを変えても前のものは残る)。抽選には出ない。
- 配るペース: 直近 1 年の出場 (2025-10〜2026-10) を当てはめると、いちばん多く出た人 (172 大会) で約 2.0 年で全部引き切る (前半 1,389 件・後半 3,304 件、2026-10-14 時点。目安 = 最速で 2 年)。
- 将来の予定 (ユーザー): 大会申請で 1 つ、参加確定で 1 つ、1 試合で 1 つ、勝ちで 2 つ。出来事の数え方 (`drawTargets`) を足すだけで同じ仕組みに乗る。

## 同期 (毎回のビルドの後)

`tools/titles/sync_owned.mjs` (spsp_scripts の build.yml が、日本の r2 の回のビルドの後に spsp-web の main から取って動かす。鍵 = Secrets の `TITLE_SYNC_KEY`)。

1. `title_export` で今の記録を全部読む (2,000 人ずつ。読めなければ何も書かない)。
2. 各 `players/<uid>.json` から回数・メインキャラ・都道府県を出し、`advanceTitles` で新しく引く。
3. 変わった人だけ `POST /api/title_sync` に送る (1 回 500 人・1.5 MB まで)。1 人分 = `{ uid, prev, bits, n_pre, n_post }`。
   Worker は **行が prev のままのときだけ** 書く (無ければ作る)。ほかの同期と重なったら書かずに `conflicts` で返し、次の回が読み直して引く。
   ビット列を減らす・回数を戻す送り方は弾く。一覧に無い番号も受ける (Worker の一覧が道具より古いことがあるため。表示と保存の確認は一覧にあるものだけ)。
- 選手のファイルは読むだけで書かない (配信の中身には入れない)。`--api` は必ず指定 (既定値なし。preview の記録は `--api https://spsp-web-preview.tosakazu.workers.dev/api`)。
- 読み書きの量: 読み = 記録の行数 (2.2 万行) × 同期の回数、書き = 変わった人だけ (その日に大会に出た人)。初回だけ全員分。

## 表示・編集

- カード (`js/player_card.js`): `model.title = { pre, post }` (文字)。片方・両方が空でもよい。空でも名前の位置は変えない。
- プレイヤーページ: 文字は `GET /api/card` の `title_text` (`{ pre, post }`、Worker が一覧から引く)。**一覧 (titles.js) は読まない**。
- 編集ページ: 持っているものは `GET /api/titles?uid=&lang=` (`{ bits, updated }`。記録が無ければ `updated: null` で「次のランキング更新で配られます」)。
  前半・後半ごとに「なし」+ 持っているもののリール。NEW。「獲得 n / 全体」(全体 = 持っているもの + まだ引けるもの。ほかのキャラ・都道府県のものは入れない)。
  一覧を読むのはこのページだけ。API の無い ConoHa のプレビューだけは、記録の代わりに出た大会から計算して見た目を確かめる (`simulateTitles`)。
- お知らせ (`js/title_notice.js`): ログイン中は全ページのヘッダーが本人の記録を 6 時間ごとに読み、前に見たビット列より増えていれば人型アイコンに赤い点、
  メニューに「新しい二つ名 (n)」。編集ページを開くと既読 (このブラウザの localStorage にビット列)。一覧は読まない (ビット列の比較だけ)。
- フォント: 「コーポレート・ロゴ ver2 Bold」(LOGOTYPE.JP、SIL OFL 1.1、予約フォント名なし)。二つ名の文字だけに絞り、文字の範囲ごとに 14 ファイルに分けた woff2
  (`tools/fonts/build_title_font.mjs` → `site/fonts/title/<番号>-<ハッシュ>.woff2` と `site/css/player_card.css` の unicode-range)。
  ブラウザは表示する文字を含むファイルだけ読む (カード 1 枚で平均 90 KB、全部で 340 KB)。**二つ名を足したら作り直す** (テストが足りない文字を見つける)。

## Worker

- `card_put` の `title`: id の形 (`^[a-z]{2}-\d{4}$`)・一覧にあること・その位置に使えること (`usableIn`)・記録にあること (`title_owned`。
  記録がまだ無い選手は `unlock: 'initial'` のものだけ。日本の一覧には無い)。選手のデータ (R2) は読まない。
- `card_get`: 設定と `title_text`。
- `title_get` (`GET /api/titles`、だれでも)、`title_sync` / `title_export` (鍵つき)。`worker/src/api/title_owned.ts`。
